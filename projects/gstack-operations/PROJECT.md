# GStack Operations

The CTO owns execution readiness, not an invented product sprint. Company import creates configuration, agent instructions, skill bridges and the backlog onboarding issue; it does not authenticate Claude, install Bun/browser binaries, create a product workspace or activate a workforce.

## Activation and authority

Keep imported agents paused and timer heartbeats disabled until the operator selects otherwise. The operator activates the CTO, reviews and authorizes **onboard**, identifies the actual execution account/HOME (including remote runners), and approves any installation/browser-download scope. Move that issue from backlog to an actionable assignment when ready. Activation alone is not permission to replace an existing gstack installation or access paid/cloud/mobile/browser-session services.

The CTO loads `gstack-runtime`, performs read-only identity/readiness checks first, and provisions only when the issue explicitly authorizes it. A matching complete runtime is reused without changes. Foreign, dirty, incompatible or mismatched installations remain untouched; request a dedicated execution account/HOME or explicit reviewed maintenance. There are no schedules or recurring tasks in this project.

## Durable outputs

Store readiness evidence and pending board decisions in the Paperclip onboarding issue/documents or operator-approved shared workspace. Record the real upstream pin/version, source digests, native registration identity, provider availability, tooling/build/browser statuses, workspace/repository access, commands and exit statuses, unexercised checks, blockers and next owner. Never store credentials or mistake an optional unavailable service for a pass.

Finish onboarding only for the operator-selected execution scope. Enable only the agents the operator selected, respecting the host's permissions; if agent activation is board-only, return the exact operator action instead of bypassing it. A ready host still needs a concrete product brief. The operator sends that brief to the CEO in Paperclip; the CTO creates the actual project/workspace assignments. Do not hard-code a machine directory or launch a sprint from this operations issue.

Reviewed updates originate in this company repository's catalog/lock and a reviewed reimport. Execution-host maintenance is a separate authorized action. Never use a generic Paperclip upstream skill update or an agent-triggered rolling gstack upgrade as a substitute.
